denext runs your project on its own build of Deno: the CLI, `denort` (what `deno compile` and
`denext build --compile` build onto) and the Deno Desktop runtime, all from the public
[Brainwires/deno](https://github.com/Brainwires/deno) fork. It is stock Deno 2.9.8 plus the
additions below. You don't install it: denext downloads the build it pins, checks its SHA-256 and
runs every command that needs Deno on it ([denext's Deno toolchain](/docs/toolchain)).

This page lists everything the fork does differently from stock Deno that you can see or use: the
APIs, flags and variables it adds in the first sections, and the fixes and smaller behavior
differences it carries, by area, in [Fixes and smaller differences](#fixes-and-smaller-differences).
Changes with nothing to see (tests, CI, build scripts, refactors) are described only in the fork's
[DENEXT.md](https://github.com/Brainwires/deno/blob/development-denext/DENEXT.md). The tables of
the first sections give each runtime version in full (`2.9.7-denext.15`, `3.0.0-rc.6`,
`3.0.0-denext.21`); the release history is in
[Our Deno Desktop runtime](/docs/desktop-runtime#runtime-releases).

## Which runtime am I on?

From runtime `3.0.0-rc.3` the runtime says whose it is, so code needn't infer it from the version
number (there is no upstream Deno 3.0; denext checks the marker too):

```ts
if (Deno.build.denext) {
  console.log(`denext's Deno ${Deno.build.denext}`); // "3.0.0-denext.21"
} else {
  console.log("stock Deno: Deno.SQL and the other additions are not here");
}
```

```text
$ deno --version
deno 3.0.0-denext.21 (stable, release, aarch64-apple-darwin)
v8 15.6.75.57-rusty
typescript 6.0.3
denext 3.0.0-denext.21 (Brainwires)
```

| What                       | Detail                                                                                                                                                                                            | Since        |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------ |
| `Deno.build.denext`        | The runtime's version, a string, in the main thread and in workers. `undefined` on stock Deno.                                                                                                    | `3.0.0-rc.3` |
| `deno --version` last line | `denext <version> (Brainwires)`; `deno -V` stays one line.                                                                                                                                        | `3.0.0-rc.3` |
| `Deno.version.deno`        | The fork's own version (`3.0.0-denext.21`), also in the user agent (`Deno/3.0.0-denext.21`). Before `3.0.0-rc.1` it was `2.9.7-denext.N`.                                                         | `3.0.0-rc.1` |
| `deno upgrade`             | Refuses to run in a release build, and the background update check is off: upstream's channels would replace the fork with stock Deno. Use `denext upgrade` or `denext toolchain install`.        | `3.0.0-rc.1` |
| Release channel            | `deno --version` says `stable`, the channel of the Deno release the build is made from (2.9.8). `npm` `engines.deno` ranges are checked against that release, not against the prerelease version. | `3.0.0-rc.1` |

The versions sort in release order: `2.9.7-denext.1` … `2.9.7-denext.22`, then `3.0.0-rc.1` …
`3.0.0-rc.6`, then `3.0.0-denext.1`, `3.0.0-denext.2`, … (there is no `3.0.0-denext.4`, `3.0.0-denext.9`, `3.0.0-denext.11`, `3.0.0-denext.14` or `3.0.0-denext.15` release, nor any between `3.0.0-denext.18` and `3.0.0-denext.21`). That is semver's order with one
exception: denext ranks the `3.0.0-denext.N` releases above every `3.0.0-rc.N`, where plain semver
would put them below. There is no upstream 3.0: upstream Deno stays on its 2.9.x LTS line, and
denext's runtime is the forward line. Every "Since" cell below names the full release: a
`2.9.7-denext.N` row comes from the first line (`2.9.7-denext.1` to `2.9.7-denext.22`), which sorts
before every `3.0.0` release, so `2.9.7-denext.16` is not `3.0.0-denext.16`. `3.0.0-denext.14` and
`3.0.0-denext.15` were never released; their work shipped in `3.0.0-denext.16`. No release between `3.0.0-denext.18` and
`3.0.0-denext.21` was published; that work shipped in `3.0.0-denext.21`.
Every row below applies to the runtime denext pins (`denext toolchain status` names it); a later
release's rows are added once denext pins it. Before the marker (`3.0.0-rc.2` and earlier) denext recognises its runtime by the version alone ([Versions](/docs/toolchain#versions)).

**Required from denext 5.0 (planned).** Today every denext command still has the stock-Deno
escape hatch, `DENEXT_DENO=stock`, and what needs the fork falls back or says why it can't. From
denext 5.0 the plan is to require denext's runtime: the stock-Deno fallbacks go away, and features
such as `Deno.SQL`, the jail and native TypeScript 7 stop being optional. Until 5.0 ships, nothing
changes for a project on stock Deno.

## JavaScript and TypeScript APIs

### `Deno.SQL` and `Deno.sql`

A built-in SQL client for Postgres and SQLite with Bun's `Bun.sql` surface and no npm. Every
interpolated value is sent as a parameter, never spliced into the text. Since `2.9.7-denext.15`, the first release with the fork's own CLI archive; stock Deno has none
(its nearest is `npm:postgres`). The Postgres side of [Database](/docs/database#postgres) and
`postgresClient()` run on it.

```ts
const sql = new Deno.SQL(Deno.env.get("DATABASE_URL")!, { max: 10 });
const users = await sql`select id, name from users where id = ${id}`;
await sql`insert into users ${sql({ name: "Ada" })}`;
await sql.begin(async (tx) => {
  await tx`update accounts set balance = balance - ${n} where id = ${from}`;
  await tx`update accounts set balance = balance + ${n} where id = ${to}`;
});
```

`timestamp` as local wall-clock time, arrays, enums, ranges and geometry as objects. Postgres runs
over the runtime's own TLS stack (`sslmode` `disable` to `verify-full`, client certificates,
Unix-socket hosts); `--allow-net` is checked for the host and for each address it resolves to.
SQLite needs read (and, unless read-only, write) permission for the file. Not yet: MySQL.

## Permissions and network behavior

Deno's permissions are least-privilege guardrails: checks inside Deno's own APIs, not an OS
sandbox. A subprocess, FFI or a native addon goes around them, unless the run asks for kernel
enforcement: the opt-in `--kernel-sandbox=enforce` (Landlock and seccomp on Linux, Seatbelt on
macOS) holds them for `deno run` / `deno serve`, with documented gaps; the default applies nothing.
The grants that amount to full trust, symlinks and allow scopes,
and how network rules behave with a proxy are on [Permissions](/docs/permissions).

| Behavior                                  | What                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Since             |

## Deno Desktop APIs

[Our Deno Desktop runtime](/docs/desktop-runtime), which says why it exists and how it is tested.

## Fixes and smaller differences

The fixes and smaller behavior differences denext's Deno carries over stock Deno 2.9.8, by area:
crash and hang fixes, Node.js compatibility, Windows process behavior, the Deno Desktop runtime's
packaging and updater, and security updates. Each applies to the runtime denext pins; where a
fix came from an open upstream pull request, it behaves as that pull request describes. Security
fixes that name an advisory link it on the fork's
[security advisories](https://github.com/Brainwires/deno/security/advisories) page.

### CLI commands

| Behavior                                     | What                                                                                                                                                                                                                                                                                                                                                            |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--watch` and a SIGTERM from another process | A SIGTERM sent by another process stops `deno run --watch` (`node --watch`), as Ctrl+C does, even while a restart is under way: without a listener the program ends by the signal, and with one the listener runs and the watcher exits 0 after a 500 ms grace. The restart's own SIGTERM and a program's `process.kill(process.pid, "SIGTERM")` don't stop it. |
| `--inspect-brk` with an early debugger       | Under `--inspect-brk` the runtime counts as paused on start as soon as the inspector is registered, so a frontend that connects while the main module still loads gets `NodeRuntime.waitingForDebugger`, and a `Runtime.runIfWaitingForDebugger` sent then resumes it.                                                                                          |
| `deno add` / `deno install <pkg>` errors     | `npm:x was not found` only when the registry answered 404; a connection failure, a 5xx or a stalled download fails with `Failed loading package information for npm:x from <registry>` and its causes.                                                                                                                                                          |
| JSR manifest load errors                     | When a JSR package's manifest fails to load, the error lists the cause under it (a refused connection, a download deadline's per-attempt report) instead of ending at `failed.`                                                                                                                                                                                 |
| `deno doc --json`, `--html`                  | Output carries no ANSI color escapes (a template literal type's `repr` included), whether or not stdout is a terminal; a plain `deno doc` keeps its colors.                                                                                                                                                                                                     |
| Signals during `deno task`                   | `deno task` listens for every signal before it starts the task, so a signal that arrives as the first child starts is forwarded instead of ending `deno task` (a `SIGTERM` used to orphan the child) or being dropped.                                                                                                                                          |
| `deno compile` with a seed                   | `deno compile` warns when it records a seed: under `--seed`, every run of the program repeats its `Math.random` and cryptographic values; under `--deterministic`, only `Math.random` repeats and the cryptographic sources stay random. | Workspace member globs                       | Expanding member globs (`packages/*/deno.json`) and every include-based file walk (`fmt`, `lint`, `test`, `bench`, `doc`, tsconfig roots) skip directories no include pattern can match under, such as a member's `.venv` or build output; the same files are found. | Cached 404s and auth tokens                  | A request that carries credentials (a `DENO_AUTH_TOKENS` entry for the host, or an explicit auth header) skips a cached 404 and asks the server, so setting the token after a failed anonymous import works at once instead of after the 15-minute cache or `--reload`.                                                                                         |

| `RUST_BACKTRACE=1`                           | An ordinary error (such as a failing `deno test`) prints without the CLI's own Rust stack; panics still print theirs.                                                                                                                                                                                                                                           |

### Processes, signals and Windows

| Behavior                                      | What                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Handle inheritance on Windows                 | A child process inherits only its own stdio and the handles it is given (the IPC pipe, npm's state file), so a spawn made at the same moment on another thread no longer holds its output pipe open and its `.output()` (or `execFile` callback) no longer waits for an unrelated long-lived process. Applies to `Deno.Command` and `node:child_process`.                                                                                                                                  |
| Piped child output on Windows                 | A piped child's stdout and stderr (`Deno.Command`, `Deno.run`) are read through the I/O completion port, so a quiet child no longer holds one of the runtime's blocking threads. Many concurrent piped children (a build's or a `deno test --parallel` run's) no longer exhaust the pool and hang every later spawn.                                                                                                                                                                       |
| Worker output pipes on Windows                | The runtime's own async pipes (how `deno test` reads each worker's stdout and stderr) hold no blocking thread while a read waits, so a `--parallel` run with many workers leaves threads for file system and subprocess work.                                                                                                                                                                                                                                                              |
| Piped stdin and child pipes on Windows        | A child's piped stdin, the runtime's pipe writers and `node:child_process`'s blocking pipe reads hold no blocking thread while they wait, so children that don't read their input yet can no longer fill the pool and hang the parent.                                                                                                                                                                                                                                                     |
| Concurrent spawns on Windows                  | A process the runtime starts without a handle list (internal helpers, the type checker) never inherits another spawn's pipe ends, so a concurrent `Deno.Command` child's output closes when that child exits.                                                                                                                                                                                                                                                                              |
| Pseudo-terminal spawns                        | On Windows a `.bat` / `.cmd` program's arguments are escaped as `Deno.Command` escapes them, so an argument can't start a second command through cmd.exe; the ConPTY pipes are private to the process, the child never picks up the parent's redirected handles, and a NUL in an argument is refused. node-pty's `destroy()` closes the terminal at once. Not covered: a child that ignores the dispose signal hangs `await using`, and `cols` / `rows` above 32767 are clamped by ConPTY. |
| Resource limits while idle                    | Under `--max-memory`, `--max-cpu-time` or `--max-time` an idle program stays asleep: the watchdog sleeps until there is something to check instead of waking 50 times a second. The limits, exit codes and messages are unchanged.                                                                                                                                                                                                                                                         |
| Console close, logoff and shutdown on Windows | When a `SIGHUP` / `SIGTERM` listener takes a console close, logoff or shutdown, the process is held until the listeners have returned and the promises they returned have settled, at most 5 s for a console close and 20 s at logoff or shutdown (what Windows allows); a second signal is delivered meanwhile. A listener that drains should return a promise that settles when the drain is done, or exit itself. Ctrl+C, Ctrl+Break and events no listener took return at once.        |

| `deno compile --exclude` paths                | An `--exclude` or `compile.exclude` entry (also used by `deno desktop`) matches however the walk spells the path: `../`-relative entries and a working directory behind a symlink, inside a local `node_modules` too. `--exclude-unused-npm` still prunes only the global-cache snapshot.                                      |

### Core runtime and crashes

| Behavior                                     | What                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Buffers backed by shared or resizable memory | An op given a view of a `SharedArrayBuffer` or a resizable `ArrayBuffer` (`fs.readSync`, `crypto.randomFill`, `TextEncoder.encodeInto`, `Deno.readSync`) works on a private copy and writes back only the bytes it changed, so a buffer shrunk or written by another thread during the call no longer crashes the process or loses those writes. A raw pointer still points at the buffer itself.                                     |
| Crash and hang fixes from upstream           | Inspecting a revoked `Proxy` prints `<Revoked Proxy>`, a polluted `Object.prototype.signal` no longer overflows the stack, `a.readable.pipeThrough(b)` no longer deadlocks, `deno fmt` no longer runs out of memory on conditions that flip each other, `deno lint --fix` keeps file modes, a closed `Deno.watchFs` releases its watch at once, and `--watch` survives a re-raised SIGTERM and kills `unref()`'d children on restart. |
| Where a panic is reported                    | The CLI's and a packaged desktop app's panic message points at the fork's issue tracker (`github.com/Brainwires/deno/issues`), not upstream's; the release's symbol archives decode its stack trace.                                                                                                                                                                                                                                  |
| Copying the runtime's internal collections   | A runtime-internal set or map built from another `Set` or `Map` copies it instead of hanging or throwing, which fixes the OpenTelemetry trace-state copy.                                                                                                                                                                                                                                                                             |
| Cross-thread tasks wake the event loop       | A task spawned from another thread (a native addon's threadsafe-function call, a worker's cross-thread spawn) always wakes an idle event loop; such a loop could stall until something else polled it.                                                                                                                                                                                                                                |
| SQLite initialization at startup             | SQLite's process-wide initialization finishes once before the cache databases open in parallel, so the occasional startup crash on macOS arm64 (`EXC_BAD_ACCESS` at pc 0 on a tokio worker) is gone.                                                                                                                                                                                                                                  |
| `import()` during top-level await            | `await import(x)` of a module whose top-level `await` hasn't finished (one the main module is still evaluating, or an async dependency of it) resolves after the evaluation finishes, with initialized exports.                                                                                                                                                                                                                       |
| Malformed source maps                        | A stack trace through a module whose source map points out of range keeps the generated location instead of a bogus line (or a panic in a debug build).                                                                                                                                                                                                                                                                               |
| OpenTelemetry export of Latin-1 text         | Log bodies and span, event and metric names and attributes with accented Latin-1 characters are exported intact under `--unstable-otel` / `OTEL_DENO=true`, not as U+FFFD.                                                                                                                                                                                                                                                            |

### Security updates

| Behavior                                           | What                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Rust dependency advisories                         | Every RustSec advisory with a fixed release is fixed in the runtime's dependencies (rustls, the Postgres crates under `Deno.SQL`, zip for `deno upgrade` and `deno compile`, quinn-proto, quick-xml, crossbeam-epoch, …). The one accepted exception is rsa RUSTSEC-2023-0071 (no fixed release; RSA PKCS#1 v1.5 decryption in WebCrypto and `node:crypto`).                                                                                                                                                                                                                                          |
| Hardening carried from open upstream pull requests | `process.debugPort` needs `--allow-sys=inspector`; a self-reference `require()` of the package needs `--allow-read`; `tty.ReadStream` / `WriteStream` check the descriptor's permissions; a CR or LF in a `node:http` proxy request target is refused; npm package names used in cache paths are validated; an EC public key not on its curve is refused at import.                                                                                                                                                                                                                                   |
| DNS resolver (RUSTSEC-2026-0119)                   | The DNS resolver is on hickory 0.26, free of the quadratic name compression of RUSTSEC-2026-0119. `node:dns` with explicit servers reports a refused server as `ECONNREFUSED` instead of a timeout and an undecodable answer as `EBADRESP`; `Deno.resolveDns()` returns only the answer section and `getServers()` keeps the configured order.                                                                                                                                                                                                                                                        |
| Install, cache and descriptor checks               | A remote module whose body fails its checksum is not written to the HTTP cache, so a later load downloads and checks it again. Dependency aliases and workspace package names must be `name` or `@scope/name` before an install links them, so an install writes only inside its package folders. `node:fs` `fchmod` / `fchown` / `futimes` need write access to the path the descriptor was opened with, and adopting a descriptor the isolate doesn't own (a pipe or TCP wrap, `dgram`'s `UDP.open(fd)`) needs all permissions; one received in an IPC message belongs to the isolate that read it. |
| Elliptic-curve crypto (RUSTSEC-2026-0387)          | WebCrypto and `node:crypto` elliptic-curve keys, signatures and ECDH run on constant-time big-integer code, clear of RUSTSEC-2026-0387. P-521 ECDSA signatures are now RFC 6979 deterministic, like every other curve (both forms verify everywhere); a prehash shorter than half the field is still refused (P-384 with SHA-1 fails to sign).                                                                                                                                                                                                                                                        |
| AppImage packaging and zstd                        | `deno desktop`'s AppImage writer compresses with the workspace's zstd 0.14, so no copy of zstd 0.13 (RUSTSEC-2026-0391, -0398, -0403) is built in; the image is standard zstd SquashFS 4.0 as before.                                                                                                                                                                                                                                                                                                                                                                                                 |
| The Deno Deploy token on Linux                     | `deno deploy` keeps its token in the Secret Service over an encrypted session (`dh-ietf1024-sha256-aes128-cbc-pkcs7`), so it no longer crosses the D-Bus session bus in clear text for another process on the bus to read. | V8 security updates                                | The runtime's V8 follows Chrome Extended Stable's branch, which still receives upstream security fixes, and carries the security merges Chrome ships there; a release build fails when the V8 or CEF pin falls behind its branch. `deno --version` names the exact V8 build.                                                                                                                                                                                                                                                                                                                          |
| V8 fixes for bugs exploited in the wild            | The runtime's V8 carries the fixes for CVE-2026-85046 (a type confusion) and CVE-2026-87491 (an out-of-bounds write), both exploited in the wild; advisory GHSA-qr84-w8xw-f7r4.                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Timer and tick state memory                        | The memory `tickInfo`, `immediateInfo` and `timerInfo` share between Rust and JavaScript belongs to its V8 backing store, so it is never read after being freed (a crash on macOS, and freed memory copied into snapshots); advisory GHSA-mvh6-5whv-26gw.                                                                                                                                                                                                                                                                                                                                             |
| CEF backend security updates                       | The CEF backend embeds a Chromium build with Chrome's stable-channel security fixes (advisory GHSA-fp5v-5vcj-35wj for the move to Chromium 156). An elevated Windows CEF launch is restarted with the de-elevation switch so it stays elevated, with its command line, environment, working directory and handles unchanged.                                                                                                                                                                                                                                                                          |
| V8 security merges                                 | The runtime's V8 carries the security merges of its Chrome Extended Stable branch, among them CVE-2026-121057 (type confusion with module star exports) and CVE-2026-121137 (type confusion when a debugger breaks inside optimized WebAssembly; needs an inspector session).                                                                                                                                                                                                                                                                                                                         |
| `tls.checkServerIdentity` and IP hosts             | A host `net.isIP()` rejects that the WHATWG host parser would turn into an address (fullwidth digits, an ideographic full stop, a leading zero) never matches a certificate's DNS names or common name, as in Node's fix for CVE-2026-105483, CVE-2026-106069 and CVE-2026-106072.                                                                                                                                                                                                                                                                                                                    |

## What isn't here

  dependency updates that change no behavior are listed only in the fork's DENEXT.md; the fixes
  you can observe are in [Fixes and smaller differences](#fixes-and-smaller-differences), and each
  release is summarised under [Tracking Deno](/docs/toolchain#tracking-deno).
